# 自包含提交实现

`solution.cpp`只包含problem.h与C++17标准库，完整实现 `ScheduleCvGraph`。本地problem.h由官网转录；不依赖外部模拟器、JSON库、CANN、GPU/NPU。可单独编译：

```powershell
g++ -std=c++17 -O2 -Wall -Wextra -Wpedantic -I ..\include -c solution.cpp -o ..\build\submission.o
```

## 搜索与可行性

先映射稀疏ID并检查DAG。计算反向关键路径、预估前驱输出释放收益；6种拓扑优先级包含关键路径、输出释放、小分配、ID顺序、单位内存关键路径和净内存收益。为每种顺序尝试单流与不同stream数量、两类类型亲和策略。

每个候选在提交文件内准确模拟：Wait→Compute→Record、同刻流ID仲裁、独立AIC/AIV容量、workspace/output占用、直接消费者计算结束释放output、sink保留、稀疏事件。只选择合法且 `T <= deadline_us` 的候选，再严格按T、peak字典序比较。额外护栏Event影响时序，原始数据依赖与内存释放规则始终不变。

小图进行一轮有界流迁移与合法相邻拓扑交换，重建同步后重新模拟。单流只是候选，不能保证显存或deadline。无可行候选时抛出 `std::runtime_error`；这是启发式搜索未找到结果，不证明输入无解。官方接口没有公开失败返回规范，当前显式异常用于开发和本地测评，最终接入判题器时需对照其约定。

## 预算与复杂度

基础唯一评估预算：n≤512最多220；512<n≤2048最多96；n>2048最多36。精确结构签名在生成计划之前去重，哈希桶完整比较排除碰撞误剪。新增内存策略使用独立32预算，无解时图局部性回退追加16、保守资源列表追加8，避免挤掉基础候选。首批核/显存拥塞且n≤2048时，再对best计划追加最多3次Stream优先编号重排，保留每条Stream任务和所有额外guard。最多尝试256个Stream，保持确定性。尚未根据官方未公开的CPU时限设置墙钟中断预算。

单流有线性精确内存快路径。静态串行显存策略全部失败且n≤18时，子集DP求精确串行最小峰值，O(n·2^n)时间、O(2^n)空间；不保证并行最优。动态列表按“最后直接消费者”的真实释放收益排序，并尝试无权高度。剩余无解图通过低度数无向BFS的局部性/逆序排列恢复Kahn拓扑顺序后再次分流，回退规模上限10000；多分量BFS用epoch避免反复清全图数组。

记节点n、边m、使用流数S、唯一候选数B。优先队列排序约O((n+m)log n)；分流约O(S(n+m))，模拟按事件时刻推进，约O(Sn+m)加事件检查/排序；稠密生成Event用向量，外部任意稀疏Event仍用通用映射。除小图DP外，候选签名缓存使主要空间随B增长到O(B(n+m)+S)，没有按maxID/EventID分配大数组，也不分配真实张量显存。实际本地CLI约405MiB峰值包含整批JSON DOM，不代表提交函数单独空间。
