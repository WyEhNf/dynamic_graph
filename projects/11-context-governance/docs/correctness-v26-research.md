# 正确性优先：v26 研究与可证边界

证据截止：2026-10-11。此文件记录新阶段，历史 v24/报告冻结不改写。用户新目标替代前轮 35% 停止门槛。

## 目标分成两层

1. **压缩语义保护**：保留完整公开需求、目标源码、已识别依赖闭包；源码片段必须逐字来自输入。当前 Python AST 依赖分析不涵盖任意运行时动态导入/反射。无法证明无关的代码或初始化副作用应保留，预算不足明确报告超预算。精确字节/闭包检查可以验证这个转换不删已标识内容，不能因此声称任意程序语义等价。
2. **生成程序需求正确**：候选必须满足可信公开契约。有限样例、随机测试、候选多数一致均不是全输入正确证明。全域保证必须同时明确输入域、准确形式规格、程序语义和验证器可信基；仅证明模型自拟规格不能保证用户需求正确。

当前固定 30 题属已反复用于开发的 DEV 集，不能重新命名为持出集。v22 一轮最终 baseline 19/30、compressed 20/30；自拟 public examples 的预期值不可靠，不能作为可信答案。后续公开契约由公开自然语言需求推导，开发者已知历史失败，必须标记 development-informed。参考实现及现有隐藏测试只用于离线验证/最终评估，不进入生成、修复或候选排序提示。

## 主论文与迁移方式

| 原始来源 | 迁移到项目 | 边界 |
|---|---|---|
| [AlphaCodium, 2024](https://arxiv.org/abs/2401.08500), [作者仓库](https://github.com/Codium-ai/AlphaCodium) | 先分析需求/边界与简单算法，再生成多个候选；先用可信公开测试反馈，再考虑模型生成测试 | 模型生成预期不能自动升级为可信断言；论文测试集成绩不是本项目成绩 |
| [CodeT, 2022/ICLR 2023](https://arxiv.org/abs/2207.10397) | 多候选、多测试执行与交叉一致性可作为次级排序信号 | 相关错误可让多数候选共同错误；一致性不是证明 |
| [Self-Debugging, ICLR 2024](https://arxiv.org/abs/2304.05128) | 自解释 + 真实公开反例反馈 + 定向修复 | 已有 critique/self-review 未解决当前复杂任务；应给真实、可信反馈而非空泛提醒 |
| [VERINA, 2025；v3 2026-03-16](https://arxiv.org/abs/2505.23135), [作者仓库](https://github.com/sunblaze-ucb/verina) | 分别评估代码、规格完整性和证明，而非合并成一个通过率 | 正确代码与准确规格、可验证证明是不同能力 |
| [AlgoVeri, ICML 2026；v2 2026-06-03](https://arxiv.org/abs/2602.09464), [作者仓库](https://github.com/haoyuzhao123/algoveri) | 经典算法也必须带前后条件、循环不变式及验证器实际反馈 | 验证器选择、证明语言与算法结构会影响能力；不可将局部 VC 证明外推到复杂 Python |
| [Vericoding benchmark, 2025/2026](https://arxiv.org/abs/2509.22908), [作者仓库](https://github.com/Beneficial-AI-Foundation/vericoding-benchmark) | 将正式规格/证明工具作为更严格独立裁决层 | 相对正式规格正确仍需要确认规格与自然语言对齐 |
| [DafnyCOMP, ICLR 2026](https://arxiv.org/abs/2509.23061), [会议页](https://proceedings.iclr.cc/paper_files/paper/2026/hash/c04d37be05ba74419d2d5705972a9d64-Abstract-Conference.html) | 对 helper 调用、共享状态和组合行为分别检查 | 局部函数证明不能自动组成工程整体证明 |
| [Self-Spec Verifiable Code Generation, 2026-09-30 预印本](https://arxiv.org/abs/2609.39568) | 用约束显式化需求并分开评估规格覆盖、代码有效、端到端成功 | 自拟规格仍是瓶颈；此为新预印本，未据此假设本机模型可以完全正确 |

检索使用主论文、作者仓库与官方发布页；没有宣称穷尽所有最新研究。以上描述为设计迁移判断，不是复现实验。

## 当前 10 个失败的公开需求覆盖

| 任务 | 公开契约重点 | 通用验证方法 |
|---|---|---|
| intervals | reversed 必须抛 ValueError；重叠/接触合并；不改输入 | 公开例 + 覆盖集合/排序/幂等性/输入快照 |
| normalize | 每权重调用 helper；空与全零；比例；不改输入 | 公开断言 + 缩放不变性 + helper 仪器化 |
| stable_topology | 重边去重；每步最小零入度；循环拒绝；端点 helper | 小图穷举 + 独立合法性/最小选择检查 + helper 仪器化 |
| interval_gaps | 半开区间；先验证全部；界外 reversed 仍拒绝；零长不覆盖 | 有限整数域覆盖集合补集 + 验证边界 |
| sparse_product | 所有已有 entry 包括零值坐标验证；结果去零；helper | 小矩阵逐坐标公开乘法性质 + 无效零项 + 仪器化 |
| outer_join | 左顺序/右重复笛卡尔展开；右独有最后追加；不改输入 | 公开重复例 + 输出多重集/顺序性质 |
| transactional_edits | 全原值验证；helper；动作约束；失败不改输入；新字典 | 公开序列例 + 原输入快照 + helper 仪器化 |
| merge_config | 全输入验证含覆盖分支；递归替换/删除；所有字典独立 | 公开例 + 可变对象别名遍历/修改后输入不变 |
| patch_text | 原坐标；插入稳定顺序；自重叠不得误判；端点允许 | 公开坐标例 + 编辑置换（异位置）/空操作性质 |
| cache_trace | 入场 capacity helper 一次并用返回；全部过期；TTL0/LRU/容量0 | 公开时序例 + 无变异 + helper 仪器化；模型检查作为后续正式路线 |

这 10 题不是同一个输入输出模板。通用机制应接受公开测试/属性契约，不在框架内按 case_id 硬编码生成答案。原 `quality.py` 纯函数 fixture AST 限制也应作为公开运行环境契约明确给模型，避免正常类实现由于属性写入被误判；它不是一般 Python 的禁令。

## 实施与冻结顺序

1. 新 `adapters/correctness-v26` 隔离候选/公开验证/修复实现。公开 contract 数据与 suite spec SHA 绑定；不要改历史源码或测量结果。
2. 通用候选循环：先多算法考虑，生成候选；用公开测试真实执行，记录反例；限定轮次修复。全候选耗尽仍失败明确报告，不把 ABSTAIN 计正确；可信公开测试通过只标记 PUBLIC_CHECKED。
3. 旧 30 题全部通过是必要 DEV 回归目标；另外冻结新独立任务与未用于反馈的评估集。明确任务何时被冻结、是否见过、随机种子、测试哈希与评价调用次数。持出失败不得用于调参后继续称持出。
4. 精确压缩保护检查与候选功能结果分别记账；生成程序若正确而压缩漏需求仍不能算通过。
5. 形式保证路线：复杂算法需要 reviewed 规格、列表/字典/别名及循环语义。受限无循环整数 Z3 VC 仅是基础验证器演示，不能替代这些 10 题或作为唯一交付。超时/unsupported 返回未知，有限检查不提升为 PROVED。

## 更强公开模型的资源与成本

首选兼容现有环境的 [官方 Qwen3-8B](https://huggingface.co/Qwen/Qwen3-8B)：8.2B、36 层、32 Q/8 KV heads、原生 32768 上下文，Apache-2.0；现有 transformers 4.57.6 高于官方最低 4.51。BF16 原文件约 16.4GB；NF4 裸权重约 4.1GB，嵌入/元数据及未量化层使实际占用更高。4096 token FP16 KV（36×2×8×128×2×4096）约 576MiB；这些是估计，实际显存/CPU RSS 必须测量。RTX5070 Laptop 7.96GiB、CPU RAM31.3GiB；下载前 F 盘43.6GB空余，预留至少10GB给其它项目与结果。更大 MoE 即使 active 参数少，也要存储全部参数，不能假设 80B/3B active 可放入8GB显存。

本轮先固定两个既有 DEV 复杂任务短烟测，种子/候选/输出预算事前冻结。thinking 按官方 temp0.6/top_p0.95/top_k20 采样，禁止套旧 greedy。原始生成全部保留；仅 `</think>` 后最终答案进入代码验证；思考 token/时间计入成本。思考未闭合或输出截断不得挑其中代码充当最终答案。候选提示不含参考代码、隐藏测试及其结果。烟测不证明稳定性，不证明比旧模型强，不计正式成绩。

## 新阶段实际证据

- `adapters/correctness-v26/contract-manifest.json`：初版10个失败任务公开契约，参考10/10通过，历史v22失败候选10/10拒绝，CPU63.01秒。6个通用协议单测通过。
- 扩展30契约v26初稿误把helper调用约束写成只调用一次/指定顺序，拒绝了合法的partition_even双列表推导；这个是公开测试错误，不是新发现的模型需求错误。历史初稿证据保留。
- `adapters/correctness-v27/contract-manifest.json`：修正普通helper约束为至少覆盖每个输入，只有cache_trace明确exactly-once保留严格次数。全30参考通过，旧v22公开契约20/30。未重复测量未改语义的契约，按AST相同复用兼容审计；改变契约重新运行。
- `artifacts/compression-protection-all30-v27.json`：650 Token预算下30/30通过已识别闭包、源顺序和源码/保护文本逐字验证，CPU0.6217秒，实际GPU未初始化。这不是任意Python运行时语义等价证明。
- `fixtures/correctness-holdout-v28`：两个新算法任务，准备时模型调用0；wildcard_match有10,571个小字符串/模式穷举组合与Unicode/类型边界；range_updates小两操作序列穷举与固定种子大输入，公开检查独立存放。参考和占位校验CPU14.898秒。仅新增有限任务覆盖，不是赛事官方持出数据。
- Qwen3官方ModelScope锁的config.max_position_embeddings为40960，而模型卡给出的原生训练上下文为32768；短烟测不接近两者上限，二者口径分别记录，不把配置可接受长度当完整验证过的上下文能力。
