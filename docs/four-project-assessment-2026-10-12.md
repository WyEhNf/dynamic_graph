## 11 题上下文治理

### 当前进度与要求差距

题面要求重要性分析在 100ms 内完成，并以生成质量不劣化作为压缩和 TTFT 得分的前提。现有 131072 Token 分析实验最高 p95 为 53.84ms，证明该有限 CPU 工作负载满足时限，未进行 128K 模型推理。旧 30 题 DEV 一轮完整 19/30、压缩 20/30，输入 Token 加权减少 82.33%、第一 Token 端到端时延逐题平均改善 83.02%，但仍有错误代码，不能称完整正确。多阶段批评还曾出现成对退化，因此不能默认增加复核就会提高质量。

公开契约修订版已覆盖 30 题，参考全部通过，旧候选 20/30；650 Token 下已识别保护闭包及源码逐字保留检查 30/30 通过。Qwen3 旧烟测只有加载完成的 partial 文件，没有完成质量结果。32K 缓存验证属于容量和 ID 一致性证据，与工程功能正确分开。

### 技术与抽象模型

技术包括 Python AST、TypeScript Compiler API、依赖检索、精确 Token 计数、带保护约束的预算选择、去重、会话缓存、量化推理、KV 卸载、公开属性测试和成对评测。当前治理核心使用标准库，模型环境单独隔离；本机约 8GB GPU 限制大模型选择与并发能力。

把上下文看成带权片段集合，每个片段有 Token 成本、相关度、历史效用和依赖边。选择集合 S，满足预算、保护项和依赖闭包，优化压缩成本与端到端时延，并附加生成质量约束 Q(S)≥Q(full)。难点是 Q 不能由片段打分精确预测，动态导入和初始化副作用也无法仅靠静态 AST 证明无关。摘要可能改写要求，公开测试可能漏边界，自拟期望可能错误；候选通过有限测试只应标记公开检查通过。

### 提升空间

继续提高压缩率的边际价值较低，优先把公开可信反例反馈接入候选修复、拒绝截断思考内容、记录全部调用成本，再开展新的工程任务成对评测。目标是先解决目前复杂需求的质量缺口，再判断是否保持 25% 压缩和 TTFT 收益。达到任意工程全域正确没有可信概率；DevEco 和 ArkTS 工程接入仍是独立交付工作。

### 学界与业界参考

[LLMLingua 2](https://arxiv.org/abs/2403.12968) 将压缩建模为 Token 分类，可参考其双向重要性分析，但自然语言基准效果不能证明源码语义安全。[AlphaCodium](https://arxiv.org/abs/2401.08500) 的测试驱动候选流程和 [Self Debugging](https://arxiv.org/abs/2304.05128) 的执行反馈适合当前质量缺口。迁移时保留可信公开契约，模型生成期望不能自动成为真值；本项目已有 TypeScript 编译器基座，可用于工程符号与类型闭包。

## 18 题 ISA 调度

### 当前进度与要求差距

题面以完全正确为首要门槛，Level 1 平均 COPY 比例不超过 10%，Level 3 不超过 2%；本地题面快照没有明确 Level 2，也未明确比例分母和平均权重。原 336 图保持 272 合法、47 个严格模型内无解证书、9 个预算失败和8 个调度失败。通用区域搜索后的 COPY 为 192859，合法子集等权 COPY/输出均值 13.5842%。

最新移动节点与固定骨架交错的 84 图验证有 9 图改善、总 COPY 123→87；45 节点手工图 13→0，保存的矩阵 160 图 64→62。这证明新邻域确有作用，不证明完整 336 图收益，更不证明官方 Level 达标。该方法保持隔离，默认算法未变。

### 技术与抽象模型

技术包括 Basic Block DAG、寄存器 RAW/WAR/WAW、拓扑排序、物理槽位年龄、COPY 接力、beam、A* 有界搜索、不可变路径标签、小图精确 oracle、符号和整数差分重放。

设最大回溯距离 W=2^bit_width。每个原节点执行一次，输入必须在最近 W 个真实输出槽内；COPY 会占用一个新槽并延长某个原值身份的可用寿命。搜索状态包含已执行集合、仍活跃的身份及年龄、寄存器状态和已插入 COPY 数。优化目标是在合法拓扑序中最小化 COPY，同时满足运行预算。难点是 COPY 本身又使其他值老化，共享值的多消费者要求和寄存器副作用耦合，局部最优邻域可能跨不过较长固定骨架。

### 提升空间

当前实得均值与必要下界之间约有 3.30 个百分点的空间，但必要下界未必可同时达到。优先验证新移动节点方案在原 336 图的覆盖和真实收益，再针对 17 个未知失败提高可行性搜索。若保持当前固定 272 图、严格身份模型及等权输出口径，10% 和 2% 均低于已证明下界，应转向明确官方允许的变换与评价口径，不能通过更换分母或删除失败图宣布达标。

### 学界与业界参考

[Min Reg Scheduling](https://arxiv.org/abs/2303.06855) 同时探索 CP SAT 精确求解和启发式寄存器压力调度，可参考共享消费者分组，但低压力不保证低 COPY。[LLVM MachineScheduler](https://llvm.org/doxygen/MachineScheduler_8cpp_source.html) 的就绪队列、上下调度及寄存器压力控制可参考；本题的年龄窗口比一般寄存器容量约束更强，需要保留物理槽位状态。[OR Tools CP SAT](https://developers.google.com/optimization/scheduling/job_shop) 可以作为小规模约束调度裁决器；经典作业车间示例没有 COPY 接力语义，需要额外建模，不能直接替换现有求解器。

## 19 题动态算子图

### 当前进度与要求差距

题面要求分析朴素或分块 Cholesky C 源码生成符号依赖 Metadata，面对 N=3 至 10000 的动态形状进行 FP64 计算；结果完全一致为硬门槛，Metadata 占 15 分、计算性能占 85 分，IO 不计计算分。

当前已具备 C AST→字节码→Metadata→VM 和经证明适用的块 DAG 原生执行；一般稠密 N10000 已与真实 C 的全部 800000008 字节输出核对。历史 13 源配对计算中位耗时减少 52.16% 至 80.58%，范围仅为该对照。新的 LOAD+LOAD 融合成本批 190 份原 C 输出约 817MB 全比对通过，但连续 VM 对照为 46 胜、42 负、1 平，不能推广为通用加速。预算证明和嵌套证明仍是可选实验，不混入固定预算默认。

### 技术与抽象模型

技术包括 Clang AST、C++20、字节码解释器、源控制流与读写依赖、符号循环、任务 DAG、多核调度、packed 存储、AVX2/AVX512 检测、严格浮点语义、二进制流和执行预算证明。

将 C 程序视为控制流与带下标的内存访问系统，先提取参数化迭代域及依赖，再在动态 N 下实例化任务。优化不仅要保证数学上的 Cholesky 结果，还要保持源 FP64 运算顺序、符号零和显式 FMA 语义；因此分块、向量化和并行必须有适用性证明。核心难点是一般 C 的别名与控制流、依赖提取可靠性，以及保持逐字节一致时可合法利用的并行度。字节码派发消除会增加预处理与代码体积，短任务可能变慢。

### 提升空间

最有价值的是基于真实 PROGRAM 分析可安全融合的区域与控制流入口，解释为什么 LOAD 对在部分源码变慢，再决定下一个执行优化。对已经优化充分的 native 路径不预设大幅空间。源码支持扩展必须配独立原 C oracle；任意 C 支持与稳定官方 85 分性能均没有当前保证。

### 学界与业界参考

[MLIR Affine](https://mlir.llvm.org/docs/Dialects/Affine/) 提供参数化循环和访问表示，可参考其依赖分析边界；[Polygeist](https://acohen.gitlabpages.inria.fr/impact/impact2021/papers/IMPACT_2021_paper_1.pdf) 展示 C 到 Affine MLIR 的路线。[LAPACK DPOTRF](https://www.netlib.org/lapack/explore-html/d2/d09/group__potrf_ga84e90859b02139934b166e579dd211d4.html) 可参考成熟分块分解结构，但其调用 BLAS 和重排运算并不保证与本题源程序逐字节相同。

## 27 题 AI Core 多流调度

### 当前进度与要求差距

题面要求返回满足 deadline 的合法多流方案，先最小化计算完成时间 T，再最小化显存峰值。workspace 与 output 在 Compute BEGIN 同时申请，workspace 在 END 释放，output 在最后一个原始直接后继 END 释放，sink output 留到全图完成。AIC/AIV 核池独立，不需真实 NPU。

当前默认 R51 在原 202 困难记录 145 合法，新 48 图 42 合法，合计 63 个有独立 witness 的图未解；已有大量回归、独立堆事件重放、INT64 边界与 UBSan 控制。后续两个隔离方案在固定 12 图仍为 4 成功、8 失败；因果延迟重启没有恢复，逻辑工作量还增加约 2.32%。真实观察资料已生成，README 顶部与统筹文件未完全同步，需要以最新独立验收为准。

### 技术与抽象模型

技术包括 C++17 单文件提交、异构资源调度、离散事件仿真、拓扑闭包、消费者释放 cut、显存必要界、局部迁移、有限组合搜索、事件同步和整数溢出检查。

变量为各节点流归属、流内顺序和 Record/Wait 事件；由确定性事件仲裁推导计算区间。约束同时包含 DAG、核心累计容量、动态内存容量和 deadline，目标为字典序 (T, peak)。内存占用依赖原始直接消费者完成状态，而不是简单的每任务固定资源区间。难点是一个早期生产者可能把大量 output 锁住；当前前缀进入死端后，仅在局部 cut 内重排无法恢复，需要改变较早的决策，同时避免组合爆炸。

### 提升空间

优先用真实失败状态推导必须撤销的前缀决策，开发有界回退或多个 producer 延迟，而不是继续堆叠同类单次重启。恢复 5 至 15 个失败记录属于合理研究目标，但参数变体与独立拓扑应分别统计。所有新增搜索都要计入失败路径成本；改善可行率不意味着更快。完整一般图最优性和全部隐藏有解图保证仍超出当前启发式能力。

### 学界与业界参考

[OR Tools CP SAT](https://developers.google.com/optimization/scheduling/job_shop) 可作为小图时序与容量 oracle，必须另加 END 释放、确定性仲裁和事件约束。[Checkmate](https://arxiv.org/abs/1910.02653) 的全局内存优化及 [Dynamic Tensor Rematerialization](https://arxiv.org/abs/2006.09616) 的在线存活管理可帮助理解内存瓶颈；二者允许重计算，本题当前没有该变换授权，只迁移生命周期分析思路。
