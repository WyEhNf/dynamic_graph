Use the same immutable accepted GNU runtimeb9a65378905b in both arms. The only
command variation is `--vm-budget fixed` versus `--vm-budget proved`; no source,
N, SIMD, backend, tile, scheduler or compiler change is permitted between arms.
The ordinary99a runtime, published fixed1e9 policy and default-OFF CMake flag
remain unchanged pending evidence and an explicit integration decision.

Predeclare19 cases×3 alternating pairs=114 records/57 pairs:15 genuine VM
sources and four native bypass controls. Keep all positive and negative costs,
unknown proofs, source headers, actual C reference bytes and host samples.
Separate the45 VM pairs from12 control pairs rather than blend unlike work.

and their original40M-or-more total opcounts, including existing repetition

dense four-matrix batch at7/13/29/53. They are explicitly short-task latency

The four controls reuse the true-C wire corpus: scalar AUTO dense, scalar AUTO

provenance and reference. Record actual engine, tile geometry, vector kernel and
zero proof work/time; native bypass must have no VM steps, no effective VM cap,
and not-run matrix count equal to the actual header count.

Run fixed/proved on round0, proved/fixed on round1, fixed/proved on round2,
rotating the whole19-case list by round. All cases run the same scheduler,
threads4, block7 or frozen applicable block argument, and native/AUTO rules.
The VM cohort's optimized=none Metadata ensures its actual engine is VM,
not a native source deliberately forced into an interpreter.

Every trial validates frozen source/Metadata/input/C reference/EXE SHA and full
M/N headers, then records raw stdout/stderr, full-byte C comparison, Win32
PeakWS/commit/freeRAM and host/background CPU counters. Small-batch launch RAM

mean the whole host is idle. Proof/decode cost stays inside reported compute;
analysis, I/O, process wall, external SHA and comparison times remain separate.

Per-case report all three paired compute/wall ratios and their medians,
absolute fixed/proved cost, proof time/work/bound/status counts, decode time,

policy, not a new kernel speedup. No automatic promotion threshold or selective
source removal is defined. A default policy would also need to preserve the
literal explicit-limit override and portable fallback, and remain honest about
unknown/nested/general-C coverage; that integration is a separate stage.
