# 共享归约的物理年龄搜索：候选边界

本稿是 R102 冻结后新候选的设计说明，不覆盖 R102 的源码、报告或实测成绩。

## 目标和不变量

仅接受 `recognize_reduction_columns` 完整筛选的 2–4 行共享 GET 权重、各行独立 MULW/ADD 原链、独立 SET 图。筛选保证全部原节点覆盖、唯一且读写分离的架构寄存器、每行相同权重序列、每个私有 GET 只供一个原 MULW。每个原节点执行一次；原 ADD 链、有序操作数不改。不同原数值永远没有被声明等值。

已有固定列、固定行序的候选没有新增质量收益；新候选在每列内选择私有 GET、原 MULW、原 ADD、最后列 SET 的合法就绪顺序，并允许首个私有 GET 先于该列权重 GET 出生。希望减少过早出生的权重和累加器在历史窗口中的接力。

## 状态与转移

每行保存 `(stage, accumulator_age, temporary_age)`；临时角色依次为私有 GET 输出和当前原 MULW 输出。另保存当前权重是否已经出生、其最新年龄。非零年龄表示不同物理位置的不同原身份；每个角色的消费者数量由结构和阶段重建。

一次原指令转移之前，如果最老的存活身份年龄为 W，且这次指令不是该身份的最后一次消费，先给最老身份插入 COPY。若本指令最后消费最老身份，直接执行即可。刷新时使用最新副本；该候选采用的这个规则只是固定原序列的合法发射策略，不涵盖所有可能的 COPY 插入时机。原指令、COPY 都使其他存活年龄增加一；消费结束删除旧角色，新角色出生年龄一。独立原 JSON 验证仍检查最后完整输出，不能用抽象状态代替。

默认最多一个未归约临时乘积；另有最多两个的显式实验。每次同时最多一个未消费的私有 GET，避免枚举没有明确收益的提前出生。因此搜索是受限原指令顺序空间，不能证明全 DAG 最优、不能证明原题无解。

## 行角色对称与实际值的区分

列内阶段的键排序各行的三个整数，列边界键排序各行累加器年龄。两行的实际 GET 值、原节点 ID 和 ADD 运算结果仍不同。排序只识别**资源状态的行置换同构**：全部行的未来拓扑为相同次数的私有 GET、MULW、原 ADD、SET，唯一共享输入是同一权重序列；置换不会改变任何年龄代价或可执行阶段。保留其中一个代表以及它的真实原节点路径，后续仍用代表的行映射发射原节点。因此这不授权任何值替换、GET 重读或算术重写。

如果未来支持不相同的列长度、跨行依赖、不同副作用或不同运算资源约束，这个对称合并必须重新分组或拒绝；不能直接套用。

## 搜索预算和证据要求

列内以累计 COPY 数为优先级，原指令进度只用于同费用打破平局。每列状态数及墙时有界；已完成的列边界按费用保留有限 beam。列截断、beam 截断、固定列顺序、临时乘积限制和贪心 COPY 均是搜索限制，即使一个列的 Dijkstra 完整结束，也不能宣称整个问题最优。

完整候选才物化；不完整前缀不会作为提交输出。物化重新按实际原 ID 发射，COPY 数必须与抽象成本一致；独立符号、原 JSON 身份排列和三个可配置整数检查分别验证。任何预算失败保留为预算状态，不改写为不可行证书。

最初无临时值限制的 128 节点试探，在每列 4000 状态限额前未找到完整边界，两次均是预算失败。代码随后限定临时值，待独立功能验证和匹配原负载测量；本文件此时不宣称新 COPY 收益。

## R104–R106：缓存与范围审计

缓存仅存活在一次调用内，行数、W、beam、临时值限制和状态预算在该调用中固定；不跨参数或程序保留全局缓存。键是列边界所有累加器的完整最新年龄排序，以及首列/尾列两个标志。列内 Dijkstra 键另外保存所有行的 stage、累加器年龄、临时 GET/乘积年龄、当前权重年龄及是否已经出生。首列省略 ADD，尾列允许各行 SET，必须分别建键。

原 ADD 依赖顺序由完整筛选保证：开始第 j 列时，各行前 j 列原 ADD 已全部完成，当前各行的原 ADD 只能在自身旧累加器和本列原乘积都可用时执行。未来列尚未发射任何原 GET/MULW/ADD，唯一在列边界存活的是各行累加器。列内 stage 因而完整编码待发原节点的资源角色。具体原 ID 在代表路径及计划映射中保留，不能用缓存键直接作为输出。

缓存保存抽象 `(行角色, 操作阶段)` 配方、费用和边界年龄；命中后用当前真实年龄排序对应的行排列，将配方逐项还原到当前列的原 GET/MULW/ADD/SET ID，再完整按原有序 args 发射。省略具体数值/名字/ID只是调度成本的同构，不是功能相等声明。缓存选择本列局部候选，不考虑未来列数，因此未来剩余长度不影响本列费用；这也限制了它的全局优化能力。

R103 的直接候选在原16个 dot 输入、1秒预算中11合法、4受限matcher拒绝、1预算，共同11输出974到680 COPY。R104采用缓存后12合法、4matcher拒绝，原12合法输出4112到2876 COPY，包括4095节点 W8 的3138到2196。R105同250毫秒预算，边界beam1/2/6均取得2876；该功能批观测beam1 p95约43.64毫秒，但其他项目同期功能验证仍可能影响CPU，不据此宣称隔离性能因果。

R106持出72个新输入变化2/3/4行、2/7/31/113/331/631列、四窗口、原拓扑和原MUL/ADD左右参数。旧冻结R91为62合法9预算1启发；直接候选60合法12受限matcher拒绝。共同60 COPY21716到15502，21改善38相同1退化（3行2列W8，旧0新1）；另有2个小W4旧成功而matcher拒绝。显式组合必须保留旧候选，不能凭matcher限制宣称原题不可行。全部60保存输出重新读回、原JSON身份与异初值符号/三整数独立重放通过。

后续完整组合测试沿用原336哈希和全部失败，固定冻结R102基线；本稿暂不把直接候选的成功子集比例代替全分布成绩。新快照/报告另建，不改R102冻结。
