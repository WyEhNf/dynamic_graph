## 已核实的新增要求

| 项目 | 正文要求 | 基座对应能力 |
|---|---|---|
| 问题模型 | Basic block DAG；GET 为根、SET 为叶；指令一般一或二输入、一输出 | 输入转 DAG；显式支持 GET/SET/ADD/MULW/COPY |
| 引用方式 | `t#d` 引用当前指令前 d 条指令的输出 | 解析和输出都按实际序列位置计算，不按 id 数值计算 |
| 指令距离 | `bit_width` 为 2…5；最大回溯距离为 `2 ** bit_width`，2 bit 可引用前 4 条 | 边界测试确认 `t#4` 在 2 bit 下合法 |
| 变换 | 超距离通过 COPY 接力；允许调整执行顺序，必须保持功能完全正确 | 稳定基线、就绪选择、COPY、独立结构与符号校验 |
| 输入 | `block_id`、`bit_width`、`instructions` 数组，包含 id/op/reg/inputs | 单 block JSON CLI；COPY 使用 source 字段 |
| 输出 | `block_id`、`optimized_instructions`，引用需重新映射 | 重新编号为连续输出位置，附本地 stats |
| 统计 | COPY 数量与运行耗时 | 插入 COPY / 总 COPY、两种比例口径、调度耗时 |
| 正确性等级 | Level 0 首先正确 | 本地35项回归、10000小图、符号校验和三种数值差分；不冒称官方评测结论 |
| 优化目标 | Level 1 平均 COPY 占比 ≤10%；Level 3 ≤2% | 作为后续阶段目标，当前未达标声明 |
| 评分 | 正文中的 30% 权重是示例，未固定 | 不将示例权重写成正式规则 |

## 官网示意输出需要确认

输入示意是：`GET r1`、`GET r2`、`MULW [t#1,t#2]`，乘法使用 r2 和 r1。

输出示意在两个 GET 后添加 `COPY source:t#1`，随后 `MULW [t#1,t#2]`。按正文相对距离的定义，乘法的两个操作数都来自 r2，功能改变。因此基座不照搬该输出；`test_website_illustrative_copy_example_is_not_equivalent` 会拒绝它。此处记录的是按引用定义推导出的示意不一致，需由官方确认或修正文档。

## 已采用且可替换的保守假设

1. GET读取寄存器当前值，SET将单个输入写入reg；默认只保留同寄存器RAW/WAR/WAW顺序，不同寄存器访问可重排，GET/GET没有额外顺序边。不同reg名称暂假设没有物理别名。SET输出暂与其输入相同。conservative模式才强制全部GET/SET原顺序，仅用于对照审计。
2. `ADD/MULW` 是无其他副作用的二元操作；COPY 仅传递值。调度不改变运算符及操作数顺序，不重复或删除原有算术节点。
3. 官方未定义输入 id 的排序意义，解析以数组位置建立距离；输出 id 为连续位置。
4. 启发式失败只是当前策略未找到方案；精确oracle在有限状态空间完整结束时，证明范围也仅限原DAG边保持、节点单次执行、按所选寄存器依赖、只新增COPY、不重新计算/合并等价值。不能将任何模型内无解声明直接用作原题无解证明。
5. 输出可额外包含 stats；若官方 schema 不允许，适配层去除它。

## 仍需官方澄清或获得的资源
